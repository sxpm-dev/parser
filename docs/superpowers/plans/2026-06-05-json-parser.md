# JSON Parser Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `@parser2/json` — a JSON5-tolerant input parser whose `render` output matches `JSON.parse` on strict-JSON inputs and whose `stringify` output matches `JSON.stringify` byte-for-byte (no-arg form).

**Architecture:** New parser package under `packages/json/`. One monolithic schema (`src/schema.ts`) with mutually-recursive node types: `JsonNull`, `JsonTrue`, `JsonFalse`, `JsonNumber`, `JsonString`, `JsonArray`, `JsonMember`, `JsonObject`, and a `JsonValue` dispatcher. `JsonObject` uses the same `merge`+`dynKey` pattern CSS's flat-json target uses. `rootType: 'JsonValue'`, `defaultTarget: 'ast'`. All runtime parser code is generated by `@parser2/compiler`; `src/index.ts` only re-exports `./_generated/parser.ts`.

**Tech Stack:** TypeScript (NodeNext), `@parser2/parser` DSL, `@parser2/compiler` codegen, node:test runner, tinybench (via shared `scripts/bench-table.ts`).

**Companion spec:** `docs/superpowers/specs/2026-06-05-json-parser-design.md`

**Architecture invariants (non-negotiable, repeated from `AGENTS.md`):**
- The parser package is ONLY: `src/schema.ts`, `src/_generated/parser.ts`, `src/index.ts` (just `export * from './_generated/parser.ts';`), tests, benches, fixtures, package metadata.
- The compiler is domainless. Do NOT add JSON-specific branches in the compiler. Every behavior must come from generic schema primitives.
- If a JSON-driving need surfaces a missing primitive or compiler gap, fix it generically in the compiler. Do not add handwritten JSON logic in the package.

**Runtime API note:** the runtime option key is `target`, not `type` (see existing usage in `packages/css/test/*.ts` and `packages/yaml-block/test/*.ts`):

```ts
render(input, { target: 'ast' })
stringify(value, { target: 'ast' })
```

```ts
import { $, defineSchema, literal, parse, relation, span } from '@parser2/parser';

// JSON parser schema. Root is JsonValue, which dispatches to the
// JSON value type productions. Strict-JSON-only at this stage;
// JSON5 extensions are layered in later tasks.

export default defineSchema({
  rootType: 'JsonValue',
  defaultTarget: 'ast',
  punctuators: {
    lbrace: '{', rbrace: '}',
    lbracket: '[', rbracket: ']',
    colon: ':',
    comma: ',',
  },
  tokens: ['number', 'string', 'comment'],
  examples: [
    // --- JsonNull --------------------------------------------------------
    relation('JsonNull', {
      input: 'null',
      encodings: {
        parse: parse([literal('null')]),
        ast: null,
        source: 'null',
      },
    }),

    // --- JsonValue: dispatcher (grows as productions are added) ----------
    relation('JsonValue', {
      input: 'null',
      encodings: {
        parse: parse([
          span('node', 'null').of('JsonNull'),
        ]),
        ast: $.node,
        source: $.node,
      },
    }),
  ],
});
```

Two notes for the implementer:
1. `source: 'null'` is a scalar template body — see the "Render bodies" table in `docs/example-first-structure-dsl.md`.
2. `source: $.node` on the dispatcher lets the inverse delegate to the matched production's own `source` template.

## Task 4: Add JsonNumber

**Files:**

- Regenerated: `packages/json/src/_generated/parser.ts`

JSON number grammar (RFC 8259): optional `-`, integer part (`0` or `1-9` then digits), optional fractional part (`.` + digits), optional exponent (`e`/`E`, optional sign, digits).

We use the schema's `number` class. The closed refinement set scopes per shape (`int`, `float`, `scientific`). For strict-JSON coverage we declare three `JsonNumber` productions — one per shape family. This matches the example-first principle ("One example per shape").

That's spec risk #1 surfacing — the generic `number` class capture should yield a JS number, not the source slice. Fix is in the compiler's emit layer for the `number` class capture. File the issue, port the fix, regenerate, and continue. Do NOT add a per-package coercion in `packages/json`.
