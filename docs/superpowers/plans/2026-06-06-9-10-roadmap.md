# Roadmap: 7 → 9–10 / 10 (engine / features / use cases)

Authored 2026-06-06 after shipping the iso-duration, rrule, pg-select, and
toml parser packages. This plan is the result of an honest read of where
the engine stands today and what concretely moves it toward
field-defining quality.

Scope: code, features, and use-case fit. **Out of scope** for this plan:
docs, website, package structure, npm publication, marketing. Those
matter; they're tracked elsewhere.

## Today's read (~7/10)

| Dimension | Score | Why |
|---|---|---|
| Idea / concept | 9 | Example-driven schemas + multi-target bi-directional encodings + domainless straight-line codegen is sharp and novel. |
| Source code | 6.5 | Clean pass-oriented compiler with strong invariants, round-trip check, differential fuzz. But three parallel grammar implementations (v1 emit, v2 emit, interp), several known bugs, refactoring mid-flight. |
| Features | 6 | Substantial implemented set; real holes: `.operator()` not in v2, no TS type inference, `raws` mode unimplemented, list-slot inverter can't split, multi-prod dispatch slow. |
| Usage / DX | 5.5 | Happy path pleasant; unhappy path brutal (engine bugs, no type output, verbose boilerplate). Schema authors must understand compiler internals. |
| Use cases | 7 | Excellent fit for small structured DSLs with desirable canonical formatters; broad applicability within the niche; adoption blockers are maturity-shaped. |

## Phase 1 — One source of truth for grammar execution

**Why first:** three parallel implementations of every primitive
(`packages/compiler/src/emit/` v1, `packages/compiler/src/emit/v2/`,
`packages/compiler/src/interp/`) are the source of most known gaps.
Every other phase is cheaper after this lands.

**Known matrix bugs surfaced in prior sessions:**

All three previously-listed bugs have been resolved — kept here as a
crossed-out checklist for traceability:

- ~~`.operator()` v2 throws~~ — fully wired in v2 at
  `emit/v2/span.ts:962+` (and exercised by `binary-operators.test.ts`,
  `pratt-fuzz.test.ts`, `feature-parity.test.ts`). pg-select's
  N-productions-per-operator workaround is now removable as a separate
  schema cleanup.
- ~~`sep: ''` infinite-loops the interp~~ — promoted to a hard
  `CompilerError` at codegen time in `infer/validate.ts:50` with a
  message pointing the author at a non-empty separator literal.
- ~~`stopBefore` missing from DSL docs~~ — documented at
  `docs/example-first-structure-dsl.md:514` (Modifiers table entry on
  `.repeats({...})`).

**Scope:**

1. Build a **feature-parity matrix** as a test file
   (`packages/compiler/test/feature-parity.test.ts`). Rows = primitives
   (every class × refinement × modifier × modifier-option × schema
   declaration). Columns = implementations (`interp`, `v1`, `v2`). Cells
   = `impl` / `gap` / `n-a`.
2. For each gap: implement the missing side, OR remove the primitive
   from the spec (delete from `packages/parser/src/types.ts`,
   `relation.ts`, and the DSL doc). Bias is implement-don't-delete
   unless the primitive has zero users.
3. Concrete near-term fixups: wire `.operator()` in v2; make `sep: ''`
   a `CompilerError` at codegen instead of a runtime loop; add
   `stopBefore` to `docs/example-first-structure-dsl.md` (Modifiers
   table).
4. Decide whether v1 emit is retired. My read: yes — keep v2 + interp
   only. If retiring, remove the unreferenced files under
   `packages/compiler/src/emit/`.
5. Wire the differential fuzzer (`packages/compiler/src/fuzz/`) as a
   hard CI gate: every primitive must show `interp ≡ v2` on its

**Acceptance:** `feature-parity.test.ts` is green; CI is red if any cell
is `gap`. Differential fuzzer is a hard gate.

## Phase 2 — Round-trip completeness (spec rule 5 universal)

The defining engine claim is bi-directional. Today's gaps:

**1. List-slot inverter doesn't split by separator.** After
`npm run generate -w @parser2/iso-duration`, see
`packages/iso-duration/src/_generated/parser.ts` around line 1024:

```ts
captures.date = (Array.isArray(__s.slice(__pos))
  ? __s.slice(__pos)
  : [__s.slice(__pos)]).map((__e) =>
    __dispatchInverse_DateUnit_source(__e, __indentCol)
);
```

The captured chunk is wrapped as a single-element array instead of
being split on the schema-declared separator. New compiler pass needed:
`inferListSlotInverter` — when a slot is `.repeats({sep})`, the inverse
template scanner must split the captured chunk on `sep` before
per-element dispatch.

This is the single largest correctness gap. Unblocks every multi-element
schema; today's workaround is artificial single-element examples (see
why `@parser2/rrule` uses `'FREQ=DAILY'` as its `Rule` example instead
of `'FREQ=DAILY;COUNT=10'`).

**2. Substring discriminator has false positives.** The dispatcher in
`packages/compiler/src/emit/inverse.ts` uses `value.includes(literal)`
for string-target discrimination. A SQL `SELECT` whose captured string
literal contains `' LIMIT '` mis-dispatches. Fix: if any production's
body can capture a `string` class, refuse the substring-includes path
at codegen and require a position-anchored discriminator (or error
demanding an explicit `withInverse`).

**3. `@parser2/js-expr` schema using operator precedence.** Ship a new
parser package with the existing `operators:` layered-precedence
declaration + the now-wired (Phase 1) `.operator()` span. Prove forward
parse + inverse round-trip across all precedence layers. Validates the
Pratt path that's been declared-but-unused since day one (compiler
README admits: "operators path not exercised yet because the CSS
schema doesn't use it").

**Acceptance:** no schema in the repo carries a `KNOWN_EXCLUSIONS` list;
`packages/compiler/src/check/round-trip.ts` has no skip branches;
the four shipped parsers can use natural multi-element examples.

## Phase 3 — Type inference output

The single biggest DX gap. Today `render()` returns `unknown` — every
test file in `packages/*/test/` casts:

```ts
const { render, stringify, validate } = mod as {
  render: (input: string, options?: { target?: string }) => unknown;
  stringify: (value: unknown, options?: { target?: string }) => string;
  validate: (input: string) => void;
};
```

This works but feels wrong. The schema HAS all the type information; the
compiler just doesn't emit it.

**New compiler pass `inferStructureTypes`.** For each node type, derive
a discriminated-union TypeScript type from the union of `.render(target,
body)` shapes across all that node's productions. Capture types follow
from class + refinement:

| Capture | TS type |
|---|---|
| `.number().int()` | `string` |
| `.number().int().coerce()` | `number` |
| `.ident()` | `string` |
| `.string().doubleQuoted()` | `string` |
| `.of('NodeType')` | inferred union for that node |
| `.of('A', 'B', 'C')` | `A \| B \| C` |
| `.optional()` | `T \| null` |
| `.repeats()` | `T[]` |
| `.until([...])` | `string` |

Emit `packages/<schema>/src/_generated/parser.d.ts` alongside
`parser.ts` (or types inline — either works). Schema authors write zero
types; types are derived.

**Acceptance:** snapshot test per parser package asserts the emitted
`.d.ts` matches a checked-in baseline; `render(...)` and `stringify(...)`
return non-`unknown` types in every consumer; the `as { render: ...; }`
casts in existing tests delete cleanly.

## Phase 4 — Formatter / preservation modes

Opens an entire new bucket of use cases (postcss-class tooling,
format-preserving codemods).

- Add `whitespace: 'preserve'` to `WhitespacePolicy`. Today the type
  is `'standard' | 'significant'` only; the prior roadmap entry
  referred to `'preserve'` as "declared but not yet wired" but the
  declaration isn't actually in `types.ts`. Wire it through tokenizer
  + parser + rebuild.

  **Phase 4b v1 shipped** (2026-06-07):
  - `'preserve'` added to `WhitespacePolicy`.
  - v2 production emit accumulates every inter-span whitespace slice
    into a local `__ws: string[]` and surfaces it on the captures
    payload (`{ __production, __ws: __ws, ... }`). Tail-mode
    productions (shared-dispatch alts) skip the capture — they don't
    make sense for preserve semantics.
  - `emit/rebuild.ts` introduces a new `Piece` variant
    (`kind: 'wsSlot', index`). `synthesizePieces` emits a `wsSlot`
    between every consecutive pair of spans when
    `schema.whitespace === 'preserve'`, and `piecesToConcat` resolves
    it at runtime to `captures.__ws[index]` (with empty fallback for
    callers that hand-build captures).
  - `interp/parse.ts` mirrors `__ws` accumulation; `interp/stringify.ts`
    now delegates pieces synthesis to the shared `synthesizePieces`
    so the wsSlot handling stays single-source-of-truth.
  - `'preserve'` schemas are excluded from structured fusion
    (`canFuseStructured` — same gate Recovery uses). The fused path
    bypasses the captures envelope; preserve needs `captures.__ws`,
    so it falls through to the captures path.
  - Render-targets validator whitelists `__ws` as a legal capture
    reference for preserve schemas, letting authors write
    `__ws: $.__ws` on their AST view to thread the captured ws
    through inverse derivation without changing the closed
    StructureRef vocabulary.
  - Test: `packages/compiler/test/whitespace-preserve.test.ts`
    covers v2 + interp byte-exact round-trip across ASCII-space,
    multi-space, tab, no-ws, and mixed inputs; also asserts the
    `'standard'` baseline still canonicalizes to a single space.
  - Net effect on shipped parsers: zero (all in-scope schemas use
    `'standard'` — generated SHAs unchanged).

  **Phase 4c v1 shipped** (2026-06-07, same session): auto-attach
  `__ws` to every object 'ast' AST in a preserve schema. Three
  symmetric points:
  - `emit/render.ts:emitBuilder` wraps the object body with
    `Object.assign(..., { __ws: captures.__ws })` so the AST is
    self-describing.
  - `infer/invert.ts:deriveInverses` appends a synthetic `__ws:
    $.__ws` inverse field to every `kind: 'object'` IR so stringify
    knows to extract `value.__ws` back to `captures.__ws`.
  - `infer/structure-types.ts:inferStructureTypes` adds `__ws:
    string[]` to the inferred TS type for the matching object AST
    bodies, so callers see the property in TypeScript.
  - `interp/parse.ts:renderSlotAst` mirrors the runtime attach on
    the interp side.

  The test in `packages/compiler/test/whitespace-preserve.test.ts`
  was updated to drop the explicit `__ws: $.__ws` opt-in — schemas
  now get byte-exact round-trip from a clean `ast: { type, k, v }`
  render body. Net effect on shipped parsers: zero (no in-scope
  schema declares `'preserve'`).

  **Phase 4c v2 shipped** (2026-06-07, same session): per-iteration
  ws inside `.repeats()` arrays.
  - `emit/v2/span.ts:emitRepeatsSpan` now declares
    `const __<name>_iws: string[] = [];` and tracks `__prevItemEnd`
    when the schema is preserve, the span has a sep, and the span
    is named. After each successful push it archives
    `input.slice(__prevItemEnd, __itemStart)` — the inter-iteration
    region including the separator AND surrounding ws.
  - `SpanContext` gained `preserveWs`; `SpanBindings` gained
    `iwsExpr` so the production-level emit can forward
    `<name>_iws: __<name>_iws` into the captures payload.
  - `emit/rebuild.ts` extends `SlotJoin.sep` with optional
    `iwsRef`; `joinOf(span, preserveWs)` tags every named-repeats
    join with the iws key; `piecesToConcat` emits a
    `__rebuildSlotIws(value, iws, fallbackSep)` call that
    interleaves `items[i]` with `iws[i-1]` (falling back to the
    static sep when the iws array is missing or shorter — defense
    against hand-built ASTs).
  - `REBUILD_SLOT_RUNTIME` now ships `__rebuildSlotIws` alongside
    `__rebuildSlot`. This changes the SHA of every generated
    parser (the runtime preamble is unconditional); the gate was
    relocked in this commit.
  - `emit/render.ts:emitBuilder` auto-attaches `<name>_iws` for
    every named-repeats span in the production (alongside `__ws`).
    `infer/invert.ts:deriveInverses` synthesizes matching inverse
    fields; `infer/structure-types.ts` adds `string[]` typing for
    each.
  - `interp/parse.ts:parseRepeatsSpan` mirrors the capture and
    sets `captures.<name>_iws`; `interp/parse.ts:renderSlotAst`
    forwards the field; `interp/stringify.ts:concatPieces` handles
    the new `iwsRef` join with a local `rebuildSlotWithIws`.
  - The compose test
    (`packages/compiler/test/recovery-preserve-compose.test.ts`)
    now asserts byte-exact round-trip across iterations (e.g.
    `'a : b; c : d'` survives intact through render → stringify
    even with a recovery alt in the dispatcher).

  **Phase 4c v3 mostly shipped** (2026-06-07, same session):
  - **Block comments between spans** round-trip for free. The
    inter-span skip slice that builds `__ws[i]` already includes
    `/* ... */` comments when the schema declares the `comment`
    token class — covered by the
    `whitespace:preserve preserves block comments between spans`
    test.
  - **Leading/trailing ws around optional spans (named + unnamed)**
    now round-trip byte-exactly. Named optionals carry presence
    via the nullable captured value (existing optional-fuse path);
    unnamed optional literals are tracked in
    `captures.__litPres[i]` with a new `Piece.optLit` variant in
    the rebuild path. Slot-leaf inverter
    (`__invertSlotLeaf_<target>`) was fixed to preserve booleans
    verbatim so `__litPres` survives the AST round-trip.

  **Phase 4c v4 shipped** (2026-06-07, same session):
  - **Comments between `.repeats()` iterations.** The sep-sweep in
    `emit/v2/span.ts:emitRepeatsSpan` now also eats `/* ... */`
    block comments alongside whitespace when the schema declares
    the `comment` token class AND none of the repeats roles
    consume comments (the `rolesConsumeComments` guard prevents
    swallowing what CSS treats as a Comment child node). The
    interp mirrors via `sweepWsAndComments(schema, state,
    rolesConsumeComments)`. Test:
    `v2: whitespace:preserve handles comments between repeats iterations`.
  - **Leading/trailing ws on the root parse.** The public
    `__parse` captures the leading slice (ws + comments when
    applicable) before invoking the root and the trailing slice
    after the root match but before EOF, attaching both to the
    captures payload as `__leadingWs` / `__trailingWs`. The
    public `render()` wrapper forwards them to the AST when the
    schema is preserve; the public `stringify()` wrapper prepends
    `value.__leadingWs` and appends `value.__trailingWs` around
    the inverse output. Hand-built ASTs that lack the fields
    round-trip unchanged. Test:
    `v2: whitespace:preserve preserves leading/trailing root whitespace`.

  Phase 4 is now closed end-to-end for the v1/v2/v3/v4 scope.
  The composition test
  (`packages/compiler/test/recovery-preserve-compose.test.ts`)
  validates that recovery (4a v1/v2) and preserve (4b v1, 4c
  v1/v2/v3/v4) interact cleanly.

  **Phase 4c v5 shipped** (2026-06-07, same session): JSON5 line
  comments end-to-end.
  - Schemas opt in via the `tokens` declaration:
    `tokens: [..., { class: 'comment', refinements: [{ name:
    'line', args: ['//'] }] }]`.
  - `emit/v2/production.ts` and `emit/v2/index.ts` extract the
    markers and extend the inter-span ws-skip, the repeats
    sep-sweep, and __parse's leading/trailing skip to also consume
    `<marker>...\n` runs. The leading skip in __parse runs for ALL
    comment-aware schemas (not just preserve) so JSON5 input like
    `// note\n42` parses without needing a Comment production.
    The `rootConsumesComments` guard prevents the leading skip
    from eating CSS-style block comments that the root's
    role-ladder claims as Comment children.
  - `interp/parse.ts` mirrors with `skipWsAndCommentsTopLevel` +
    `sweepWsAndComments` + `collectLineCommentMarkers`.
  - Net effect: 4 JSON5 line-comment tests unskipped, no
    behavior change for non-opt-in schemas.

  **Phase 4c v6 shipped** (2026-06-07, same session):
  first-declared-wins inverse relaxation + string-class
  refinement-aware first-byte signatures.
  - `infer/invert.ts:tolerateIndistinguishableInverses` runs
    after `deriveInverses` and before
    `validateInverseDiscrimination`. For each pair of productions
    with the same non-object inverse shape (bare ref, dynKey,
    merge, array, scalar of same value, template), it clears the
    LATER production's `inverseDerived`. The emit's
    `emitInverter` loop now skips productions with undefined
    `inverseDerived`. Object collisions are NOT tolerated — they
    require explicit literal discriminators.
  - `emit/v2/role-ladder.ts:classFirstBytes` now respects string
    quote refinements (`doubleQuoted`, `singleQuoted`, `backtick`)
    so two productions like `"hello"` (double-quoted) vs `'hello'`
    (single-quoted) get disjoint first-byte signatures and pass
    the dispatch ambiguity check.
  - `packages/json/src/schema.ts` adds single-quoted JsonString
    and unquoted JsonMember productions. Net effect: 5 JSON5
    tests unskipped (single-quoted-string, stringify
    canonicalizes single-to-double, unquoted-identifier-key,
    unquoted-multi-entry, stringify canonicalizes unquoted-to-
    quoted).
- Implement `mode: 'raws'`: capture source byte ranges + interleaved
  trivia (whitespace, comments) into a sidecar map attached to each
  AST node. `stringify(astValue, {target:'source', mode:'raws'})` uses
  the sidecar to emit byte-exact source for unmodified subtrees.
  (Partial today: per-node `source: { start, end }` is attached on
  captures in raws mode, but the interleaved-trivia sidecar isn't.)
- Implement `.recovers({...})` codegen. Today the production carries
  a `recovery: RecoveryPolicy` field but no v2 emit consumes it — a
  schema marked `.recovers({...})` silently does nothing on malformed
  input. The codegen needs: a skip-ahead-to-syncAt helper in the
  runtime; recovery-alt emission that uses it; a diagnostic
  registry in parser state. THEN add the public `onDiagnostic`
  callback so callers can observe partial-parse outcomes.

  - Public `Diagnostic = { code, drop, start, end }` exported from

  - `render`, `validate`, and the interp's `interpretParse(*)` accept
    `{ onDiagnostic?: (d: Diagnostic) => void }`.
  - `State` carries a `diagnostics` array. A production with
    `recovery` set pushes one entry just before successful return.
  - Speculation-rewind: every production snapshots
    `state.diagnostics.length` at entry; failure-return paths
    truncate, so a rolled-back alt leaves the diagnostic list
    identical to its pre-entry state. The v2 emit rewrites the
    truncation into every `state.pos = entryOff; return null;`
    site for recovery alts; the interp mirrors the same
    snapshot/truncate inline.
  - Recovery alts are excluded from structured fusion
    (`canFuseStructured`) so the diagnostic hook stays on the
    captures path. HTML's existing recovery alts (which had been
    silently misrouting through fusion) now go through the captures
    path uniformly.
  - Test: `packages/compiler/test/recovery-codegen.test.ts` covers
    the four cases (v2 render emits diagnostic, no spurious
    diagnostic on valid-only input, validate flushes, interp
    mirror).

  **Phase 4a v2 shipped** (2026-06-07, same session): span-less
  recovery. A `.recovers({ syncAt, drop })` production with
  `parse([])` triggers an inline depth-tracked scan in both v2
  emit and interp — the parser walks forward, tracking `() [] {}`
  depth, until a syncAt literal appears at depth 0, then pushes
  a Diagnostic and returns the production's captures envelope
  with no span values. Empty syncAt rejects at codegen. Zero-byte
  matches reject at runtime (the scan must consume at least one
  char to avoid infinite-loop dispatchers). Test in
  `recovery-codegen.test.ts` covers both v2 and interp.

**Acceptance:** a CSS fixture round-trips byte-exactly through `raws`
mode when subtrees are unmodified; a schema with recovery examples
produces actionable diagnostics through the public API.

### Phase 5 design notes (added 2026-06-06 after Phase 3 + 7 landed)

**Foundation already in place:**
- `InferredSchema.operatorPrecedence: ReadonlyMap<string, number>` — derived
  from `operators: { layer: [...] }` declaration order, layer 0 = loosest.
  Test: `packages/compiler/test/operator-precedence.test.ts`.
- `InferredSchema.operatorLiterals` — longest-first scanner list for
  `.operator()` class matching (Phase 1 work).
- `.operator()` class scanning in both v2 and interp (parity matrix row
  `class:operator` is `impl`).
- `InferredSchema.binaryProductions: ReadonlyMap<string, BinaryProductionInfo>`
  — schema-shape detection of `[recursive(self), operator, recursive(self)]`
  productions with body referencing `$.left`/`$.op`/`$.right` (capture
  names are author-chosen). Two binary productions on the same node type
  is a hard error. Test: `packages/compiler/test/binary-operators.test.ts`.
  Source: `packages/compiler/src/infer/binary-operators.ts`.
- **v2 Pratt forward emit shipped** (`packages/compiler/src/emit/v2/pratt.ts`).
  When `schema.binaryProductions.get(nodeType)` is set, `emitNodeType`
  swaps the standard speculative dispatcher for a Pratt pair:
  `parse<NodeType>__primary` (speculation over non-binary alts) and
  `parse<NodeType>__pratt(state, minPrec)` (climbing loop). Loop reads
  `__precTable[op]` (per-op precedence baked from `operatorPrecedence`),
  recurses on the right operand at `prec + 1` (left-associative), and
  synthesizes a binary captures payload `{ __production:
  '<Node>#<binaryProdIdx>', <leftCapture>, <opCapture>, <rightCapture> }`
  so the existing render dispatch routes through unchanged. In raws mode
  the synthesized payload also carries a `source: { start, end }` field
  covering the whole expression's range.
- **`@parser2/js-expr` ships** with 6 declared precedence layers (logical
  / equality / comparison / additive / multiplicative / exponential) and
  12 tests covering primary productions, every layer's binding, longest-
  match, mixed numeric/identifier operands, and round-trip on no-paren
  expressions.

- **Paren-aware inverse stringify shipped** (Phase 5c). The inverse path
  detects Pratt-driven node types and emits a custom binary inverter that
  takes `__minPrec` and recurses through a Pratt-aware slot helper +
  dispatcher with appropriate `myPrec` / `myPrec + 1` thresholds (left-
  associative convention: equal precedence on the right side gets parens).
  The wrap test `if (__myPrec < __minPrec) result = '(' + result + ')'`
  emits parens when the caller's context binds tighter than this node.
  Verified by 7 `js-expr` paren-aware tests including author-built ASTs
  that force regrouping: `a * (b + c)`, `(a + b) * c`, `a - (b - c)`,
  `(a - b) - c`, `a + b * c`, `a * (b + (c - d))`. Non-Pratt parsers stay
  byte-identical (verified via the parser-package hash gate).

- **Interp Pratt mirror shipped** (Phase 5d,
  `packages/compiler/src/interp/parse.ts`). When `schema.binaryProductions.get(nodeType)`
  is set, `parseNode` delegates to `parseNodePratt(schema, info, binaryInfo, state, 0)`
  — a climbing loop that mirrors `emit/v2/pratt.ts`: primary via
  speculation over non-binary alts, longest-match operator scan,
  precedence lookup, left-associative recursion at `prec + 1`,
  synthesizes the same `{ __production: '<NodeType>#<binaryIdx>',
  <leftCapture>, <opCapture>, <rightCapture> }` payload v2 uses.
  Verified by 40 `interp ≡ v2` parity tests in
  `packages/compiler/test/pratt-interp-parity.test.ts` covering
  primaries, every precedence layer, left-associative chains, precedence
  mixing, longest-match operators (`===`/`==`, `!==`/`!=`, `<=`/`<`,
  `>=`/`>`), and deep 5-operand nesting. Round-trip check
  (`checkRoundTrip`) now exercises Pratt schemas through interp.
- Documented gap: interp deliberately keeps `.number()/.string().coerce()`
  captures as raw slices (v2 coerces). Mirroring coerce on the forward
  path would also require teaching interp/stringify to re-encode on the
  inverse direction (JSON-quote, etc.) — larger surface area. Today
  schemas using `.coerce()` round-trip correctly because interp's
  render+stringify are self-consistent.

- **Right-associative operators shipped** (Phase 5e). The `operators:`
  layer declaration accepts either a bare op array (legacy / left-assoc)
  or an object `{ ops: [...], assoc: 'left' | 'right' }`. Schema
  authoring example: `exponential: { ops: ['**'], assoc: 'right' }`.
  Inferrer derives `InferredSchema.rightAssociativeOps: ReadonlySet<string>`.
  Both v2 codegen and interp Pratt loops branch on `nextMinPrec = assoc
  === 'right' ? prec : prec + 1`. The paren-aware inverter swaps
  symmetrically: for right-assoc, `__leftMinPrec = __myPrec + 1` and
  `__rightMinPrec = __myPrec` (equal-precedence on the LEFT gets parens,
  equal-on-RIGHT doesn't). Verified by 6 js-expr right-assoc tests
  + 6 new `interp ≡ v2` parity rows covering `a ** b ** c`,
  `a ** b ** c ** d`, `2 ** 3 ** 2`, mixed `a + b ** c ** d`,
  `a ** b + c`, `a ** b * c`. Full round-trip across natural-right
  chains preserves the AST shape.

- **Unary prefix operators shipped** (Phase 5f). Schema declares unary
  via a production of shape `[operator(alts), recursive(self)]` — the
  `.operator(['!', '~'])` form scopes which operators are valid in unary
  position (pure-binary ops like `*`, `&&` are NOT detected). Compiler
  pass `detectUnaryProductions` (`infer/unary-operators.ts`) recognizes
  the shape and exposes `InferredSchema.unaryProductions:
  ReadonlyMap<string, UnaryProductionInfo>`. Alt literals are merged
  into `operatorLiterals` for the tokenizer; they're intentionally NOT
  added to `operatorPrecedence` (the climbing loop's
  `__precTable[op]` lookup returns undefined → loop breaks). Pratt
  primary (v2 + interp) leads with an inline unary-prefix scan; on hit,
  consumes the op and recurses through the primary itself so chained
  unaries (`!!a` → `!(!a)`, `!~a`) work. Inverse uses the standard
  captures-walk inverter — unary always binds tighter than any binary
  op, so no paren-aware logic is needed. `checkDispatch` +
  `canFuseStructured` skip Pratt-driven binary/unary productions
  (those don't dispatch through the standard byte-prefix path).
  Verified by 7 js-expr unary tests covering `!a`, `~a`, chained `!!a`,
  binary precedence interaction (`!a + b`, `a && !b`), full
  round-trip, and pure-binary-op rejection (`*a`, `&&a` parse error).
  13 new `interp ≡ v2` parity rows.

- **Parens-as-primary shipped** (Phase 5g) via transparent-passthrough
  detection. A production whose `ast` body is just `$.inner` where
  `inner` recurses into the same node type (with no value-altering
  modifiers) is recognized as a transparent forward-only wrapper. Pass:
  `detectTransparentPassthroughs` in `infer/transparent-passthrough.ts`
  exposes `InferredSchema.transparentPassthroughs:
  ReadonlyMap<string, ReadonlyArray<TransparentPassthroughInfo>>`.
  Inverse derivation and emission skip these productions (their value
  shape would conflict with the inner production's, and the
  paren-aware stringify already emits parens by precedence rules). The
  round-trip check skips them too — the inner production's example
  carries the round-trip property. Phase 5g also added a paren-aware
  **unary** inverter: the operand minPrec is `numLayers` (one past the
  tightest binary layer), so any binary child gets wrapped in parens
  (otherwise `!(a + b)` would stringify to `!a + b` and re-parse to
  `(!a) + b`). Verified by 6 js-expr paren tests + a full-re-parse
  round-trip suite (`a`, `(a)`, `(a + b) * c`, `a * (b + c)`,
  `a - (b - c)`, `(a ** b) ** c`, `!(a + b)`, etc.) + 12 new `interp ≡
  v2` parity rows.

- **Differential fuzz shipped** (Phase 5h,
  `packages/compiler/test/pratt-fuzz.test.ts`). Seeded LCG generates
  random expressions over the full js-expr operator alphabet
  (identifiers, numbers, parens, unary `!`/`~`, all 6 binary
  precedence layers including right-assoc `**`). Three test rows:
  500 expressions at depth ≤ 4, 100 deeply-nested expressions at
  depth 6, 200 round-trip stability tests (render → stringify →
  re-render). All 800 generated expressions pass `interp ≡ v2`
  parity AND round-trip AST preservation. Reproducibility: the seed
  is hard-coded (1337); any future fuzz drift fails the suite with
  the exact diverging input quoted in the failure message.

**Phase 5 is now closed.** Every sub-phase (5b forward emit, 5c
paren-aware inverse, 5d interp mirror, 5e right-associativity, 5f
unary prefix, 5g parens-as-primary, 5h fuzz) has shipped tests +
documentation. The Pratt expression-grammar story is end-to-end
complete:

- Forward: Pratt loop with per-operator precedence + per-layer
  associativity in both v2 codegen and the reference interpreter.
- Inverse: paren-aware binary inverter (left/right minPrec swap for
  right-assoc); paren-aware unary inverter (operand minPrec =
  numLayers); transparent-passthrough productions skipped.
- Parity: 71 deterministic rows + 800 fuzzed expressions verify
  `interp ≡ v2` across the operator alphabet.
- DX: `@parser2/js-expr` ships as the canonical Pratt parser package
  with 39 tests covering identifiers, numbers, unary, binary at all
  layers, parens, right-assoc, round-trip with explicit grouping,
  and grammar-aware validate rejection.

## Phase 5 — Performance: kill the "slow path" caveats

- **First-token-lookahead dispatch** for multi-production node types.
  Today emit/v2 uses speculative try-each (compiler README admits
  "slow; no lookahead optimization yet"). Compute per-production FIRST
  set at codegen; emit a switch on first byte; eliminate the loop. The
  pg-select dispatcher trying `alt3 → alt1 → alt2 → alt0` in order on
  every parse is the most visible symptom.
- **Lazy span capture.** If no render body references `$.name`, skip
  the `input.slice(start, end)`. Compiler README lists this as planned.
- **Bake the Pratt loop** for `operators:` declarations. Compiler
  README says `buildOperatorTable` is "not exercised yet" — Phase 2's
  js-expr schema is the first user; collaborate with Phase 2.
- Tighten the perf baselines in `packages/*/bench/perf-baseline.json`.

**Acceptance:** zero "slow path" disclaimers in any compiler README or
generated comment; multi-production-heavy schemas see 2–3× parse
throughput improvement.

### Phase 6 expansion shipped 2026-06-10

The 6.0–6.6 milestones above already shipped. This session widened
rust emit's primitive coverage from "cron / iso-duration / rrule /
pg-select / toml" to also cover the comment-class, recovery, and
rawUntil productions HTML / Markdown / CSS need. Specifically:

- **Comment-class scanner** (`emitCommentSpan` in `emit/rust/index.ts`).
  Block `/* … */` scanner with interior trimming on `.comment()`
  refinement; `skip_ws_and_comments` helper added to the preamble;
  inter-span gaps, prefix-share inter-span gaps, repeats sep-sweep,
  and the `__parse` leading/trailing skip all branch between
  `skip_ws` and `skip_ws_and_comments` based on the
  `interSpanSkipFn` helper (`schema has comment` ∧ `span doesn't
  consume comments` ∧ `span isn't optional`). The leading skip
  honours the same `rootConsumesComments` check v2 does so CSS's
  `Stylesheet → Comment` recursive role isn't pre-eaten. Unlocks
  CSS rust+bcode generation — the original question that surfaced
  the roadmap-vs-handoff divergence.
- **.recovers() codegen** (`emit/rust/index.ts`). Added a
  `Diagnostic` struct + `state.diagnostics: Vec<Diagnostic>`;
  recovery productions snapshot the vec length at entry; a post-emit
  rewrite injects `state.diagnostics.truncate(__diag_snap);` into
  every `state.pos = entry_pos; return None;` site so speculative
  rollback leaves the vec unchanged. Span-less recovery alts
  mirror v2's depth-tracked scan to a syncAt literal. New public
  `render_with_diagnostics(input) -> Result<(Value, Vec<Diagnostic>),
  String>` API exposes the vec to callers.
- **rawUntil span modifier** (`emitRawUntilSpan`). Literal-stop scan
  with single-byte and multi-char stop bucketing, optional
  case-insensitive ASCII letter folding, `requireStop` and `nonEmpty`
  refinements honored. Capture is the raw byte slice from start to
  first stop (stop not consumed).
- **Repeats loop semantics** (`emitRepeatsRecursiveSpan` rewritten).
  Old impl required the declared `sep` between every pair of items,
  which broke CSS (`a { ... } b { ... }` — the `;` between rules is
  conventionally optional). New impl mirrors v2's
  `while (sep matches)` zero-or-more semantics plus a stopBefore
  check bucketed by first byte. Acceptance: pg-select still passes
  rust-diff (the `,`+stopBefore:['FROM'] combo prevents over-eating
  on `SELECT a, b FROM t`), AND HTML / CSS now emit and round-trip
  multi-rule / multi-element inputs.
- **Stringify parameter shadowing fix.** Every per-alt stringify fn
  now takes `__value: &Value` (was `value: &Value`); fixes the CSS
  bug where `let value = value.obj_get("value")` shadowed the
  parameter, making subsequent `value.obj_get(...)` calls fail to
  compile when a schema names a span `value`.
- **Generation acceptance.** `tsx packages/compiler/src/cli.ts
  packages/css/src/schema.ts --rs` succeeds; the resulting `.rs`
  compiles via `cargo build --release` and round-trips real CSS
  inputs (rules + comments + at-rules + nested at-rules). Same for
  `packages/html/src/schema.ts` and `packages/markdown/src/schema.ts`.
- **Partial raws-mode public API.** `render_with_diagnostics` is the
  first slice of raws mode; full trivia capture (`__ws`, `__litPres`,
  `<name>_iws`, `source: {start,end}`) deferred to a future session

  codegen paths, every captures payload needs to expose trivia

### Phase 6 second-pass — 2026-06-10 (CSS round-trip)

- **rust `.until()` interior-token awareness.** `emitUntilSpan` now
  reads the schema and skips quoted regions (`"..."` / `'...'`) and
  block comments (`/* ... */`) as opaque units when those classes are
  declared in tokens. Comment ranges are tracked in a `__comments`

  Trim is now inlined in-emit (was `state.src[..].trim()`) so the
  comment-adjacency boundary check sees the trim end. Acceptance:
  CSS `a/**/ { color: red; }` captures selector as `"a"` (was

- **rust multi-role recursive stringify dispatch.** `buildSlotExpr`
  and `emitStringifyForSpan` used to hardcode `stringify_<roles[0]>(item)`,

  Rule, Declaration)). New `buildMultiRoleStringifyExpr` chains
  every alt across every role via `Option.or_else`, returning the
  first non-None result; single-role spans take the early-return
  path and stay byte-identical.
- **bcode multi-role recursive stringify.** Both
  `emitWriteRefValue` and `emitInverseTemplate` in the bytecode
  encoder now build a synthetic dispatch key (sorted role list
  joined by `|`, e.g. `AtRule|Comment|Declaration|Rule:source`)
  and pre-populate `state.stringifyOffsetsByNodeType` with the
  concatenated offset list. The runtime's `stringifySlot`
  chain-tries the combined list; each production's own discriminator
  filters wrong-typed entries. No new opcode needed.
- **bcode scanClass runtime: HEX, STRING, COMMENT.** The runtime
  scanClass now handles kinds 3 / 4 / 5 alongside the cron-era
  IDENT / NUMBER / OPERATOR. Mirrors v2 + interp scanner logic.
  Unblocks bcode generation for any schema that declares those
  classes.
- **Generation acceptance for CSS / HTML / Markdown bcode.**

### Phase 6 bytecode CSS runtime — 2026-06-10 third pass

CSS bcode generation worked; CSS bcode RUNTIME was stuck on
multiple ops. This pass closes the runtime gaps so CSS bcode
render+stringify works end-to-end for the standard fixtures.

- **SCAN_UNTIL bytecode op + .until() span emit.** The bcode
  encoder didn't dispatch on `.until()` modifiers at all (the
  SCAN_UNTIL op was declared but unused). New `emitUntilSpan`
  walks the modifier, writes SAVE_OFF + SCAN_UNTIL (count,
  flags bitmask, stops...) + SAVE_OFF + capture. Runtime
  SCAN_UNTIL handles bracket-balance (bit 0), string-skip
  (bit 1), and comment-skip (bit 2). Unblocks every schema
  whose grammars use `.until()` (CSS / HTML / Markdown).
- **CAPTURE_COMMENT_INTERIOR op.** Comment-class spans now
  capture the trimmed interior (the `.comment()` refinement is
  implicit). Mirrors v2's emitClassSpanValueExpr arm.
- **CAPTURE_TRIMMED_SLICE op.** Trim-on-capture for
  `.until({trim:true})` (the default).
- **Multi-role offset post-pass.** The synthetic dispatch key
  (`AtRule|Comment|Declaration|Rule:source`) was being populated
  inline at the first call site, so early call sites (Rule's
  nodes ref) captured offsets BEFORE later prods (AtRule)
  registered. Switched to deferred resolution via
  `state.pendingSyntheticDispatchKeys`, resolved at the end of
  encodeSchema. Without this fix, the multi-role dispatcher
  routed only to the first-emitted half of the role set.
- **Discriminator strengthening (must-be-absent).** Mirror of
  rust's buildDiscriminatorChecks absence pass. emitInverseObject
  emits absence checks (JUMP_IF_NULL → RETURN_NULL pattern) for
  every field declared by a sibling alt but not by this alt.
  Closes the AtRule#0-vs-#1 ambiguity (without it, `@charset
  "UTF-8";` stringified as `@charset "UTF-8" {}` because AtRule#0
  matched the no-block input). Top-level only — nested object
  IRs skip the check.
- **SCAN_CLASS runtime kinds HEX / STRING / COMMENT.** Already
  shipped in the prior pass; restated here for completeness.
- **Bytecode size budget bumped from 50 KB to 60 KB.** The
  runtime grew ~6 KB across these additions. The cron bytecode
  budget test is updated with a documented note; tighten back
  toward 50 KB once bytecode->JS specialization shrinks the
  generic dispatch.

Acceptance: `render(input, {target:'source'})` is byte-perfect
across the standard CSS fixtures (comments, rules, at-rules
including `@charset`, nested at-rules like `@media print {...}`,
multi-rule, !important). AST→source stringify is value-stable
for most shapes; remaining limitation is the
canEncodeInverse non-string-scalar bar (Decl#0:ast not generated
because the `important:true` literal field), so the AST
round-trip path loses !important. Forward render→source
unaffected.
