# Schema DX Implementation Plan (Phase D of codegen-perf-dx spec)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Spec: `docs/superpowers/specs/2026-06-10-codegen-perf-dx-design.md` (Phase D).

**Goal:** Typed capture refs (typos in `$.x` fail at compile time), union-group sugar, and an `--explain` codegen report — all additive, no forced schema migrations, generated output byte-identical where the change is pure sugar.

**Architecture:** D2 hinges on one insight: TS cannot capture literal key names through the global `$` proxy, so typo-safety requires a scoped-refs callback — an additive `targets: ($) => encodings` relation form whose `$` parameter is typed `{ [K in Names]: Ref<K> }` with `Names` inferred from the `parse([...])` tuple. Runtime passes the SAME global proxy; all checking is type-level. D3 reuses the registry pattern proven by `until-guard.ts`.

**Tech Stack:** packages/parser DSL types (D1, D2), packages/compiler CLI + emitters (D3), node:test + `@ts-expect-error` type tests.

### Task D2a: literal-typed spans + parse-program name inference (type-level only)

**Files:** `packages/parser/src/relation.ts`, type test `packages/parser/test/typed-refs.type-test.ts`.

- [ ] `class SpanNode<N extends string = string>` — every modifier method (`until`, `optional`, `repeats`, `of`, `ident`, `css`, `comment`, …) returns `SpanNode<N>`/`this`. `span<N extends string>(name: N, example?: string): SpanNode<N>`. `literal(text)` returns `SpanNode<never>`-flavored `Literal`.
- [ ] `ParseProgram<Names extends string = string>` phantom; `parse<T extends ReadonlyArray<SpanNode<any>>>(items: T): ParseProgram<NamesOf<T>>` where `NamesOf` extracts the `N` union from tuple members (skip `never`).
- [ ] Type test: a file compiled by `tsc -b` (not executed) asserting via assignment + `@ts-expect-error` that names infer and unions accumulate. Runtime untouched — no behavior tests needed beyond existing suites passing.
- [ ] Commit: `feat(parser): literal-typed span names + parse-program name inference`

### Task D2b: `targets` callback relation form

**Files:** `packages/parser/src/relation.ts` (+`src/ref.ts` for `TypedRefs`), tests `packages/parser/test/typed-refs.test.ts`.

- [ ] `TypedRefs<Names extends string> = { readonly [K in Names]: RefFor<K> }` where `RefFor` mirrors today's proxy surface (`span-value` ref + `.present`).
- [ ] `relation()` accepts `{ input, parse, targets, status? }` as an alternative to `{ input, encodings }`: runtime builds `encodings = { parse, ...targets($) }` with the existing global `$`. Type: `targets: (refs: TypedRefs<Names>) => Record<string, unknown>` with `Names` inferred from `parse`.
- [ ] Runtime tests: both forms produce identical `ExampleDef`s for an equivalent relation. Type test: `$.typo` inside `targets` is `@ts-expect-error`; `$.prop.present` type-checks.
- [ ] Commit: `feat(parser): typed targets-callback relation form`
